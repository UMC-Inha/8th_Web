# XSS 공격 / CSRF 공격 목차

### 기본 배경 정보

`오리진 = 프로토콜 + 도메인 + 포트`

어떤 출처(Origin)의 웹사이트가 어떤 리소스에 접근할 수 있는지를 제어하는 메커니즘

기본적인 브라우저 정책 : `Same-Origin Policy`(동일 출처 정책)

1 오리진에서 로드된 웹 페이지는 2 오리진의 리소스에 직접 접근불가

타 오리진 접근 허용 : `Cross-Origin Resource Sharing`

서버 측에서 헤더를 통해 특정 오리진의 접근을 허용가능:

```
Access-Control-Allow-Origin: https://example.com
```

## XSS 공격

#### Cross-Site Scripting

- 클라이언트 사이드 취약점
- 공격자가 웹 리소스에 악성 스크립트를 삽입해 사용자의 웹 브라우저에서 해당 스크립트를 실행함
- 공격자는 해당 취약점을 통해 특정 계정의 쿠키, 세션 정보를 탈취하고 해당 계정으로 임의의 기능을 수행할 수 있음

### 유형

| 유형         | 설명                                                      | 공격 위치                     | 예시 코드                                           | 실행 시점                    |
| ------------ | --------------------------------------------------------- | ----------------------------- | --------------------------------------------------- | ---------------------------- |
| 저장형 XSS   | 악성 스크립트가 서버에 저장되어 페이지 조회 시마다 실행됨 | 게시글, 댓글, 프로필 등       | <script>alert('XSS');</script>                      | 다른 사용자가 게시글을 볼 때 |
| 반사형 XSS   | 악성 스크립트가 URL 파라미터에 포함되어 응답에 반영됨     | 검색어, 오류 메시지, 링크 등  | https://site.com/search?q=<script>alert(1)</script> | 사용자가 링크를 클릭할 때    |
| DOM 기반 XSS | 자바스크립트가 사용자 입력을 DOM에 직접 삽입함            | URL fragment, localStorage 등 | document.body.innerHTML = location.hash             | 클라이언트 측 DOM 조작 시    |

## CSRF 공격

### 개념

- 사용자의 인증 정보를 도용해 공격자가 임의의 요청을 서버에 보내는 공격
- 로그인된 상태에서 악성 요청을 유도하면 서버는 이를 정상 사용자 요청으로 오인하여 처리함

### 발생 가능 피해

- 사용자 계정으로 송금 수행
- 비밀번호 변경, 계정 탈취
- 관리자 권한 오용 등

### 공격 흐름

1. 공격자가 만든 악성 스크립트에 사용자가 접속하거나 클릭함
2. 로그인되어 있던 사용자의 인증 쿠키가 자동으로 첨부됨
3. 서버는 요청을 인증된 것으로 인식하고 요청을 처리함

- img, form 태그 등을 통해 인증 정보가 포함된 요청 전송 가능

## XSS와 CSRF의 차이

| 구분      | XSS                                                  | CSRF                                                 |
| --------- | ---------------------------------------------------- | ---------------------------------------------------- |
| 목적      | 사용자 세션, 쿠키 정보 탈취                          | 서버로 위조된 요청 보내기                            |
| 작동 방식 | 공격자가 만든 스크립트가 사용자 브라우저에서 실행됨  | 사용자의 인증 정보를 포함해 서버에 요청을 보냄       |
| 피해자    | 웹사이트 사용자                                      | 웹사이트 서버                                        |
| 공통점    | 클라이언트 측을 이용한 공격이며 사용자를 유인해야 함 | 클라이언트 측을 이용한 공격이며 사용자를 유인해야 함 |
