### `gcTime` vs `staleTime`

- `gcTime`은 무엇인가요? 🍠
  쿼리 데이터가 더 이상 사용되지 않을 때, 메모리에서 제거되기까지의 시간
  - 기본값: 5분 (1000 _ 60 _ 5)
  - `queryClient.removeQueries()`나 더 이상 사용자가 해당 쿼리를 참조하지 않을 때,
    `gcTime`이 지나면 캐시가 완전히 삭제
- `staleTime`은 무엇인가요? 🍠
  데이터를 신선하다고 간주하는 시간
  - 이 시간 동안에는 자동으로 리패칭되지 않고, 캐시 데이터만 사용
  - 기본값: `0` (즉시 stale)
  - `staleTime`이 지나면 데이터는 stale 상태가 되고, 포커스 전환이나 리마운트 시 자동으로 refetch됨.
- 두 값을 어떤 식으로 설정하여야 `캐싱 전략에 유리`한가요? 🍠
  1. 사용자 경험이 중요한 경우 (UX 우선)
     - **`staleTime`**을 길게, `gcTime`도 길게
     - ex) 뉴스피드, 마이페이지
  2. 데이터 정확성이 중요한 경우 (실시간 데이터)
     - **`staleTime`**을 짧게 또는 0
     - **`gcTime`**은 기본값 유지 또는 짧게
     - ex) 재고 수량, 거래내역
  3. 저사양 기기나 트래픽 부담 고려
     - **`gcTime`**을 짧게 줄이기 (메모리 사용 최소화)
     - 예시: 모바일 웹, 무거운 앱
